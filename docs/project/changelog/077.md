77. **Closed one of entry 76's own flagged gaps: `migrate-disclosure`'s outer-circuit ABI is
    now empirically confirmed, not just derived by analogy.** Entry 76 built
    `migrate-disclosure` by direct structural analogy to `disclosure` (same fixed 8-field
    outer-circuit interface, different `param_commitment` shape inside it) but flagged that,
    unlike `disclosure`, its layout had never actually been measured — only assumed. This
    entry runs the same check entry 69 ran for `disclosure`: a stubbed scratch copy, proven
    for real with `bb 5.0.0`, with the resulting `public_inputs` bytes inspected directly.

    ## What was done

    - A throwaway Nargo package (`migrate_disclosure_abi_check`, scratchpad, discarded, not
      committed — never part of `circuits/oprf-identity-anchor`'s own workspace or
      `Nargo.toml` members) mirrors `migrate-disclosure/src/main.nr`'s **public** signature
      exactly: `main(comm_in: pub Field, current_date: pub u64, service_scope: pub Field,
      service_subscope: pub Field) -> pub (Field, Field, Field, Field)`. Per entry 69's own
      framing ("only the function body differed — the signature and returns were identical"),
      everything below that signature was simplified: the five salted DG1/expiry/DG2/nullifier
      values and the ten `OPRFProof`s are hardcoded local constants rather than

      under test), and both `verified_oprf(...)` calls are replaced with a `oprf_proof.beta`

      committee exists to evaluate against.
    - `nargo execute` solved a real witness against `utils::constants::SAMPLE_DG1` (the same
      fixture the `identity-anchor` lib's own tests use) with a same-day `current_date`
      (2026-08-02) and a 2040 expiry, producing the same "Return variable contains a constant
      value" warning `disclosure`/`migrate-disclosure` themselves emit for their three-zero
      return tail — expected, not a discrepancy.
    - `bb write_vk --scheme ultra_honk` + `bb prove --scheme ultra_honk` + `bb verify` all ran
