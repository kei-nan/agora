# #099 — bootstrap-lock membership freeze, auditor self-resolve fix, recovered-citizen backing fix, oracle stale-proposal recovery, QV saturating math, mobile/desktop hardening (2026-09-04)

Seven same-day fix commits (`748625f` through `b3681df`) landed back-to-back and were never given
their own changelog entry — the doc-refresh commit `0b9ed15` that landed right after them only
addressed older, unrelated findings and didn't touch these seven at all. A follow-up re-review
found six stale doc claims plus this missing entry as a result (see the same-day doc fixes to
`docs/project/pallets/legislature.md`, `emergency-council.md`, `audit.md`, `elections.md`,
`courts.md`, and `CLAUDE.md`'s Desktop Authentication section). This entry records what each of
the seven commits actually did.

## What changed

**`748625f` — close Root membership backdoor via bootstrap lock (pallet-legislature,
pallet-emergency-council).** `add_member`/`remove_member` (legislature) and
`add_council_member`/`remove_council_member` (emergency-council) were permanently
`ensure_root`-gated with no bootstrap lock, unlike the equivalent pattern
`pallet-accountability-council` already used — since a real `SudoConfig` key exists in genesis, a
compromised sudo key could unilaterally pack or purge either body at any time, bypassing
`DisclosureChecker`/`AccountabilityCouncilChecker` entirely. Adds a `Bootstrapped` storage flag and
a one-time `close_bootstrap()` extrinsic to both pallets (root, requires ≥1 member already
seated): while open, root may freely manage membership; once closed, both add/remove calls fail
unconditionally, even for root, and bootstrap can never reopen. Legislature's real ongoing
membership path (`pallet_elections::SeatLegislature::replace_members`, run every election cycle)
is untouched and keeps working after bootstrap closes. Emergency-council has no equivalent
fallback — it has no self-governance mechanism over its own composition — so closing its bootstrap
**permanently freezes** Council membership with no recourse; this is a deliberate tradeoff, not an
oversight.

**`7e288c5` — require a different auditor to resolve a flagged entry (pallet-audit).**
`flag_entry` recorded `flagged_by`, but `resolve_entry` never checked it, so the same auditor who
flagged an entry could clear it themselves — the same self-dealing bug class commit `0529508`
fixed in `pallet-anticorruption` (`clear_report` requiring a different investigator), never ported
here. `pallet-audit`'s own test suite had codified the self-clear as intended, passing behavior.
Adds a `CannotResolveOwnFlag` check mirroring anticorruption's pattern, fixes the two existing
tests that had one auditor flag-and-resolve to use two distinct auditors, and adds regression
tests asserting the self-resolve case now fails.

**`601b936` — let recovered citizens remove backing, floor seating at nonzero backing
(pallet-elections).** Two correctness bugs: (1) `remove_backing` checked `submitter == who`
against the raw `AccountId` recorded in `UsedBackingNullifier` at `back_delegate` time. After
`pallet-identity`'s `recover_account` rebinds a citizen's identity to a new `AccountId`, the
citizen can still reconstruct the same `backing_nullifier` (it depends only on their
`backing_root_secret`/slot index) but could never pass this check again, permanently inflating
`BackingCount` — which feeds legislature-seating ranking — with no recourse. Fixed by extending
`pallet_elections::CitizenChecker` with `same_citizen(former, current)`, backed by a new
`RecoveredAccountNullifier` tombstone map in `pallet-identity` that resolves through chained
recoveries, not just one hop. (2) Final seating (`sort_by(...).take(seats)`) had no floor filter,
so a candidate pool smaller than `LegislatureSeats` let zero-backing accounts get seated purely to
fill the count, indistinguishable from a genuinely elected member. Fixed by filtering out
`backing == 0` candidates before seating, leaving seats empty rather than filled by default —
verified safe since `pallet-legislature`'s motion-passage math reads live `Members().len()`, not a
fixed seat-count constant.

**`c7bd2e2` — add stale-oracle-proposal recovery path (pallet-courts).** The admin-action M-of-N
path (`invalidate_law`/`suspend_citizen` overrides) already had `clear_stale_admin_action` to
recover a proposal that never reached the Oracle Council's threshold, but the case-based path
(`submit_ai_ruling`/`finalize_ruling`) had none — if members don't participate,
`OracleActionAlreadyProposed` blocked any fresh proposal for that case forever, a real liveness
gap. Adds `clear_stale_oracle_proposal(case_id)`, matching `clear_stale_admin_action`'s
authorization/staleness model (any current `OracleMembers` member, gated by elapsed blocks since
the proposal was made). Since case-based proposals apply themselves immediately on crossing
threshold rather than sitting in an approved-but-unconsumed state, adds an
`OracleProposalProposedAt` map to track staleness for the pre-threshold proposal itself, gated by
a new `OracleProposalExpiryBlocks` config constant (wired to 14 days in the runtime, same as
`AdminActionExpiryBlocks`). Confirmed `remove_oracle_member`'s existing re-resolution logic already
covered this path correctly; no change needed there.

**`e82949c` — use saturating arithmetic in QV refund math (pallet-voting).** `allocate_budget`'s
quadratic-voting refund math used raw subtraction guarded only by surrounding if/else branches and
a prior balance check — currently safe, but would panic on underflow if a future edit weakened one
of those guards. Switches to `saturating_sub`, matching the `saturating_mul`/`saturating_add`
already used elsewhere in the same function. Pure hardening: behavior for all currently-valid
inputs is unchanged, all existing tests pass without modification.

**`7a29bef` — narrow signing-key lifetime, enable NFC MAC check, use crypto RNG for liveness
(mobile).** Three findings from a security review: `keystoreWallet.ts` cached the decrypted
`KeyringPair` (holding the sr25519 seed) for the life of the app process, despite the native
module's own doc comment claiming decryption only lasted "the lifetime of a signing operation" —
on a rooted/compromised device this was a much larger memory-dump/debugger-attach exposure window
than documented. Now decrypts fresh on every signing call and drops the reference immediately
after use (an in-flight promise is still deduped for genuinely concurrent calls, but nothing
survives past that). `NfcPassportModule.kt` had disabled BAC secure-messaging MAC verification
(`shouldCheckMAC = false`) with no documented justification found in this codebase, upstream JMRTD
docs, or issue trackers — enabled it. `RegisterScreen.tsx`'s liveness blink/turn challenge used
`Math.random()` instead of the crypto RNG (`randomAsU8a`) already used elsewhere in this codebase
for security-relevant randomness — matched the existing pattern. 356/356 mobile tests still pass;
native Kotlin changes remain uncompiled/unrun — no Android SDK/JDK in this environment, the same
standing limitation as the rest of the native layer.

**`b3681df` — scope session tokens to read, add RPC timeouts, document CSP wildcard (desktop).**
Three findings from a security review: the QR-auth `SessionRecord` carried no scope field, so
`chain_submit_extrinsic` accepted any valid session with no additional check — a latent submit
capability with nothing structurally requiring it, even though nothing calls
`chain_submit_extrinsic` today. Adds a `SessionScope` (`Read`/`ReadSubmit`) field so the command
fails closed by construction: a new `require_submit_session` check (requiring `ReadSubmit`) gates
`chain_submit_extrinsic`, separate from the plain-validity `require_valid_session` check that still
gates read-only commands. Every session minted by the QR-auth flow today is `Read`-only, so no
session that exists today can pass the new gate. The JS smoldot light-client path
(`client.ts`/`queries.ts`) had no timeout on any `api.rpc.*` call, unlike the Rust `reqwest` path's
explicit 30s timeout — a stalled smoldot response could hang the UI indefinitely; added a shared
`withTimeout()` helper (30s, matching the Rust convention) wrapping every RPC call site. CSP
`connect-src`'s `ws://127.0.0.1:*` wildcard port was flagged as broader than necessary; confirmed
the port is genuinely dynamic (discovered via `system_localListenAddresses` at connect time, not
hardcoded), so it can't be narrowed at build time — left as-is, documented why in
`discoverWsBootnode`'s doc comment instead.
