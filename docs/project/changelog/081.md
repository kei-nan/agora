# Completed next steps log — entry 81

81. **Closed the one gap changelog entry 78 explicitly left open: `migrate` and
    `migrate-disclosure` are now proven and verified end-to-end under real bb 5.0.0, using
    `oprf-committee-dev`'s DEV-ONLY simulator run twice — once for an "outgoing" committee
    generation, once for an "incoming" one.** Entry 78 built the simulator and closed
    `anchor`/`disclosure`'s "never executed" gap but explicitly did not attempt the migration
    circuits, noting the follow-on was "genuinely bounded, mechanical" work with the tools it
    had already built: "the same flow run twice, under two independent committee key
    generations... 10 `verified_oprf` calls total instead of 5." This entry does exactly that.

    ## What was built

    - `oprf-committee-dev/src/prover_toml.rs`: factored the shared `salted_dg1`/
      `salted_expiry_date`/`salted_dg2_hash`/`salted_dg2_hash_type`/`salted_private_nullifier`
      block out of `render_anchor_prover_toml` into `write_salted_fixture` (every circuit in
      the workspace takes the same fixture ahead of its circuit-specific parameters); made
      `OprfProofWitness::render` parameterizable by TOML array name (`render_named`), since
      `migrate`/`migrate-disclosure` need two `[OPRFProof; 5]` arrays (`old_oprf_proofs`/
      `new_oprf_proofs`) rather than `anchor`/`disclosure`'s single `oprf_proofs`; extracted
      `generate_proof_set` (one full committee-generation-plus-evaluation round) from what was
      previously `generate_anchor_prover_toml.rs`'s inline `main` body, since `migrate`'s
      driver needs to run that same round twice. Added `render_migrate_prover_toml`/
      `render_migrate_disclosure_prover_toml` and their `MigrateFixture`/
      `MigrateDisclosureFixture` parameter structs.
    - `oprf-committee-dev/src/bin/generate_migrate_prover_toml.rs` and
      `generate_migrate_disclosure_prover_toml.rs`: new drivers. Both use the same
      `identity_input`/`comm_in` fixture every Prover.toml in this crate already commits to.
      **The "old" side deliberately replays `generate_anchor_prover_toml.rs`'s exact recipe**
      (RNG seeded `0xA6012`, `TEST_BETA`) — since that recipe is fully deterministic, this
      regenerates byte-identical committee keys and byte-identical proofs, which is both the
      correct way to model "the committee generation a citizen originally registered under"
      and a free cross-check (see below). **The "new" side uses an independently-generated
      committee set** (seed `0xA6099`, a different beta) standing in for the post-rotation
      scheme.
    - Copied both generated `Prover.toml`s into `circuits/oprf-identity-anchor/migrate/` and
      `.../migrate-disclosure/` (input data, same precedent `anchor/Prover.toml`/
      `disclosure/Prover.toml` already set — not a circuit change).
