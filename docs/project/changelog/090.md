    ## The one deliberate, disclosed shortcut: how the test case got filed

    `Courts::file_case` requires the caller to pass `pallet-identity`'s `is_active_citizen`
    check. Becoming a real active citizen requires `register_citizen`, which needs a genuine
    ZKPassport proof (impossible — no OPRF committee, no passport hardware, this is the
    already-tracked item 1 blocker) **and**, independently, `AllowedMerkleRoots`/
    `OprfCommitteeKeys` entries, which are gated by `pallet_legislature::EnsureLegislatureMotion`
    — a genuinely real 7-day motion window (`MotionDurationBlocks = ConstU32<{7 * DAYS}>`,
    12-second blocks) that cannot be fast-forwarded on this Aura-based chain (no manual-seal
    mode exists in `node/`; block production is real wall-clock-paced). Neither gate is
    practically exercisable inside one session, and this was confirmed by reading the actual
    gating code (`pallets/pallet-legislature/src/lib.rs`, `pallets/pallet-identity/src/lib.rs`)
    before deciding what to do about it, not assumed.

    Rather than fabricate a ZK proof against the real verifier (impossible — it does a genuine
    bb 5.0.0 pairing check) or silently bypass the citizen-gate check in code (which would
    misrepresent what was tested), root's own, entirely real `System::set_storage` capability
    was used to directly write `Identity.CitizenNullifier[Alice]` and
    `Identity.ReverificationDeadline[Alice]` to the exact values `register_citizen` itself would
    have written on success. This is a standard, load-bearing Substrate/FRAME primitive (not a
    hack invented for this task), submitted as a normal `Sudo::sudo(System::set_storage(...))`
    extrinsic and confirmed by querying the resulting storage afterward. It satisfies
    `file_case`'s real `is_active_citizen` gate honestly with real on-chain storage — just
    seeded directly instead of via the currently-unbuildable full ZK-proof + 7-day-governance
    pipeline. **This does not touch, fake, or shortcut anything in `court-oracle` itself, nor
    the `submit_ai_ruling`/`finalize_ruling` round trip under test** — it only gets a case onto
    the chain for `court-oracle` to find, which is the intended precondition, not the thing
    being verified.
