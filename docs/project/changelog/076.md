# Completed next steps log — entry 76

76. **Closed entry 75's flagged gap: `verify_reverification`/`verify_migration` are now real,
    not unconditionally permissive.** Entry 75 built a genuine `AnchorProofVerifier` for
    registration only, and named the other two as the next concrete blocker — but its own
    finding ("`reverify_citizen`/`migrate_oprf_scheme` don't accept an outer ZKPassport proof
    at all") undersold the size of the fix. Verifying that claim before writing any Rust
    surfaced that reverification and migration were documented to ride on the *standalone*
    `anchor`/`migrate` circuits — the exact shape the README already calls "not safe to verify
    on-chain" for registration, for the same reason: `comm_in` is an unauthenticated private
    witness, so a prover could pair a genuine outer passport proof with a fabricated anchor
    proof. Closing this honestly needed real circuit engineering, not just extrinsic plumbing.

    ## What changed, in the circuits

    - New: `circuits/oprf-identity-anchor/migrate-disclosure` — the outer-embedded,
      pipeline-integrated form of `migrate`, exactly as `disclosure` is to `anchor`. Same dual
      old/new 5-committee evaluation as `migrate`, plus an expiry check
      (`check_expiry_from_date`) `migrate` never had — migration should require a currently
      valid passport, not just anchor continuity. Emits a single `param_commitment =
      Poseidon2(201, old_anchor, new_anchor, old_scheme_version, new_scheme_version,
      old_oprf_pk_hashes[0..5], new_oprf_pk_hashes[0..5])` (15 elements; tag `201`, distinct
      from `disclosure`'s `200`) into the fixed 8-field outer-circuit disclosure-subproof slot,
      the same "fold everything into the one commitment field" move `disclosure` made for the
      5 committee-key hashes.
    - **Reverification needed no new circuit at all.** It is exactly "recompute the anchor and
      confirm it's still the one on file" — the same shape `disclosure` already provides for
      registration. `verify_reverification` is now implemented by calling the identical
      `check_registration_anchor` function `verify_registration_anchor` uses.
    - Verified for real, not just written: `nargo compile --workspace` (5 ACIR artifacts now,
      `migrate-disclosure` at 435,707 opcodes / 558,896 circuit size — +1,967 opcodes over
      `migrate`, the same-sized increment `disclosure` pays over `anchor`), `nargo test
      --workspace` (18 tests, unchanged — `migrate-disclosure` has no tests of its own, same
      as `anchor`/`disclosure`/`migrate` before it, since `verified_oprf` cannot execute
      without a live committee), and `bb write_vk --scheme ultra_honk` under the installed bb
      5.0.0 (succeeds; VK generation needs only compiled ACIR, not a witness).
    - `README.md` updated throughout: the circuit table, a new public-input-layout section for
      `migrate_disclosure`, corrected the (wrong) claim that `verify_reverification` used the
      standalone `anchor` layout, retitled "why disclosure exists" to cover both subproof
      circuits, and updated "what the Rust verifier still has to enforce" for the 15-element
      migration commitment.

    hashes_nargo_vector` tests — nothing here was asserted from memory or derived from this
    same Rust port, matching entry 75's "the recomputation is only meaningful if it produces
    bit-for-bit the same field element the Noir circuit would" bar.
