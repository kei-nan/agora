# #091 — Project review (2026-08-18)

Full `/project-review` pass: 7 parallel read-only agents (chain core, courts+oracle,
identity/ZK/OPRF, voting+treasury+anticorruption+audit, mobile, desktop, docs-vs-reality),
synthesized below. Live inventory at review time: all 11 pallets wired at
`pallet_index` 0–18 in `runtime/src/lib.rs`'s `#[frame_support::runtime]` macro, confirmed
directly, not from docs.

**Headline: this is one of the healthier passes on record.** No critical findings. One
confirmed high-severity (already-known, now precisely characterized) security gap, one
same-commit cross-doc contradiction, one real undocumented mobile-registration gap, and a
long tail of info-level confirmations that CLAUDE.md's claims are accurate.

## Findings, ranked

### High

1. **`lookup_registered_account` trust boundary — unauthenticated RPC, no state-proof
   verification** (desktop). `desktop/src-tauri/src/commands/chain.rs:407-468` does a plain
   `state_getKeysPaged`/`state_getStorage` JSON-RPC call to a hardcoded
   `http://127.0.0.1:9944` with no proof verification. A malicious/compromised node or local
   MITM can hand `handle_auth_callback` an attacker-chosen pubkey for any nullifier, minting a
   valid session for a forged identity. This was already flagged as an open gap in CLAUDE.md's
   desktop section; the review confirmed the exact mechanism and that it is genuinely still
   open — not closed by any of the recent desktop work (smoldot migration, IPFS hash
   verification). Closing it requires moving this lookup onto the smoldot light client path
   (like the other nine read commands) so it gets real state-proof verification, or otherwise
   authenticating the RPC endpoint.

### Medium

2. **CLAUDE.md contradicts next-steps.md in the same commit on `set_oracle_account`**
   (docs-vs-reality). CLAUDE.md item 2 still says "`Courts::set_oracle_account` has never been
   called on a real chain." `docs/project/next-steps.md` item 10, touched in the *same* last
   commit (`c49fe87`) as CLAUDE.md, says the opposite: "Update, log #090: (b) is now done —
   `Sudo::sudo(Courts::set_oracle_account(...))` was called for real against a dedicated oracle
   account, confirmed via storage query," with `docs/project/changelog/090.md` documenting the
   session. CLAUDE.md needs updating — this is real, was-caught doc drift, not a
   false-alarm.
3. **`pallet-courts` oracle is single-key with no on-chain multisig** (courts). `OracleOrigin =
   EnsureOracle<Runtime>` accepts any `Signed` origin matching one `OracleAccount` value; both
   `submit_ai_ruling` and `finalize_ruling` gate solely on it. Root can rotate the key via
   `set_oracle_account`, but there's no threshold/multi-sig requirement — a single compromised
   or lost key fully controls Level-0 rulings and finalization chain-wide. Not previously
   called out this explicitly.
4. **On-device face match result doesn't gate registration progress** (mobile).
   `mobile/src/screens/RegisterScreen.tsx:282-288` — `runLivenessGate()`'s `faceMatched` result
   is logged but never branched on; the flow proceeds to `setStep('proving')` regardless of
   match success. Only the liveness challenge-response (`challengePassed`) actually blocks.
   Currently masked because the proving pipeline itself isn't built yet and throws
   `NotImplementedError` shortly after, but this is a real enforcement gap that needs fixing
   before proving ships. Not previously documented.
5. **Desktop frontend has zero JS/TS tests** (desktop). No `*.test.ts(x)` files, no
   vitest/jest in `devDependencies`, no test script in `package.json`. `client.ts`,
   `queries.ts`, `invoke.ts`, `AuthContext.tsx`, `AgentContext.tsx` are all untested at the JS
   layer — a sharp contrast with mobile's 210-test suite. Rust side (24 tests) is fine.
6. **Asset-disclosure lapsing has zero on-chain consequence** (voting/treasury/anticorruption).
   `has_current_disclosure` (`pallets/pallet-anticorruption/src/lib.rs:561-572`) is called only
   from the pallet's own tests; no consumer gates on it. CLAUDE.md's "Anti-Corruption module...
   done" framing glosses over this — already honestly noted in
   `docs/project/pallets/anticorruption.md`, but worth surfacing at the CLAUDE.md level since
   disclosure is otherwise pure record-keeping with no teeth.

### Low / Info (confirmations and minor drift)

7. **CLAUDE.md drops the `mobile/` path prefix for `android/`** (docs-vs-reality), twice
   (Current State, Remaining Work sections) — the real path is `mobile/android/`, correctly
   given in `docs/project/apps/mobile.md`. Low-risk but could send someone to `cd android` and
   fail.
8. **Second, independent emergency mechanism in pallet-executive not mentioned in CLAUDE.md's
   top-level Government Structure summary** (chain core). `pallet-executive` has its own
   cabinet-declared emergency-declare/ratify/sunset system (`vote_declare_emergency`,
   `ratify_emergency`, 2/3 supermajority) fully separate from `pallet-emergency-council`.
   Correctly documented in `docs/project/pallets/executive.md` as "a second, separate
   mechanism," just absent from CLAUDE.md's higher-level narrative.
9. **`RevocationOrigin`/`ConstitutionalOrigin` placeholder origins not flagged in CLAUDE.md**
   (chain core). Both are honestly-commented `EnsureRoot<AccountId>` placeholders in
   `runtime/src/configs/mod.rs` ("wire to a real collective for mainnet"), visible in code and
   component docs, just not called out in CLAUDE.md's origin narrative.
10. **`enact_law_internal` silently discards `AutoChallengeHook` failure** (chain core).
    `pallets/pallet-constitution/src/lib.rs:757` — `let _ = T::AutoChallengeHook::...` swallows
    any error with no event. Currently latent (the hook can't actually fail today) but not
    structurally enforced.
11. **court-oracle context-building is O(total ledger size) per case** (courts) —
    `fetch_expenditures_for_department`/`fetch_audit_entries_for_department` scan the full
    `ExpenditureLog`/`AuditLog` with no department index. Honestly flagged in-code as "does not
    scale," not hidden.
12. **`twox128_hex` desktop bug — already fixed, not open.** An earlier committee-node doc
    comment references a bug in desktop's `to_le()` usage; verified against current code
    (commit `46c0caf`, "correct twox128 storage-key hashing") — desktop, court-oracle, and
    committee-node all now correctly use `to_le_bytes()`. No action needed; noted here only to
    close the loop since one subagent's cross-reference read as a live issue.
13. **No formal benchmarking harness** across pallet-courts and the voting/treasury/
    anticorruption/audit group — hand-written `Weight::from_parts` throughout, consistent with
    the rest of the repo, not a regression.
