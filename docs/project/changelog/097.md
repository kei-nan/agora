# #097 — project review: fix pallet-elections benchmark regression, refresh stale test counts (2026-08-29)

A full project review (7 parallel agents across chain core, courts/oracle, identity/ZK/OPRF,
voting/treasury/anticorruption/audit, mobile, desktop, and a dedicated docs-vs-reality audit)
found the codebase largely clean — every previously-landed fix cited in `CLAUDE.md` re-verified
as real, zero critical/high security or correctness findings across six of the seven areas. Two
things needed fixing: a real build regression, and stale test-count claims in three docs.

## What changed

**`pallets/pallet-elections/src/benchmarking.rs`** — `cargo test -p pallet-elections --features
runtime-benchmarks` was failing 3/71 (`bench_register_as_delegate`, `bench_back_delegate`,
`bench_remove_backing`, all with `Error::InvalidProofScope`). Root cause: the delegate-persona/
backing-nullifier ZK wiring (`786b792`/`4a628d1`) added a domain-separation scope check to
`register_as_delegate` — `public_inputs[3]`/`public_inputs[4]` must equal
`AGORA_ELECTIONS_SERVICE_SCOPE`/`AGORA_ELECTIONS_DELEGATE_REG_SUBSCOPE` — but the benchmark
fixture's `delegate_persona_proof<T>()` helper never got updated to set those two indices, so it
still filled them with zeroes. Since `back_delegate`/`remove_backing`'s benchmarks both call
`register_as_delegate` as setup, all three failed at that shared call. Fixed by setting the two
indices to the real scope constants (already importable via the file's existing `use super::*;`);
`backing_proof<T>()` and the `back_delegate`/`remove_backing` extrinsics themselves were checked
and have no analogous scope check on this path, so no fix was needed there. Only
`benchmarking.rs` was touched. Now 74/74 passing with `runtime-benchmarks`, 67/67 without
(both counts grew from 66/59 as of the delegate-persona commits, independent of this fix).

**`CLAUDE.md`, `docs/project/apps/mobile.md`, `docs/project/next-steps.md`** — mobile's `npx
jest` count had drifted to 356 tests / 26 suites (the three docs disagreed with each other: 337,
300/21, and 300/300 respectively), and `pallet-identity-zk` had grown from 148 to 152. All three
docs updated to the current, independently re-verified numbers, dated 2026-08-29.
`docs/project/next-steps.md`'s pallet-elections line updated separately (see above) once the
benchmark fix's real post-fix numbers were known, rather than guessing at them ahead of the fix.

## Verification

- `cargo test -p pallet-elections --release`: 67/67.
- `cargo test -p pallet-elections --release --features runtime-benchmarks`: 74/74 (was 71 passed/
  3 failed).
- `cd mobile && npx jest`: 356/356 across 26 suites.
- `cargo test -p pallet-identity-zk --release`: 152/152.

## What was NOT changed

The review's other findings were all low-severity/cosmetic (inconsistent `dev-mode` cfg-gating on
`PassthroughAnchorVerifier`, `pallet-accountability-council` using hardcoded weights instead of a
`weights.rs`, a couple of unbounded-iterator/modulo-bias notes with no realistic exploit path at
current pool sizes, `chain_submit_extrinsic` not binding signer to session — inert since nothing
calls it yet, and a missing pair of command names in `docs/project/apps/desktop.md`'s inventory)
— left as-is per the review's own recommendation rather than churned reflexively.
