    ## What a committee actually does, and what was ported

    `TaceoLabs/oprf-nr` (vendored at `~/.nargo/github.com/TaceoLabs/oprf-nr/v1.0.0`, the exact
    git-dependency cache `nargo` itself resolves `oprf = { tag = "v1.0.0", ... }` against) only
    ever *verifies* a committee's response — it has no committee-side code at all, because
    that is `TaceoLabs/oprf-service`'s job, a separate service this project has never stood
    up. Reading `oprf/src/{blinded_query,dlog,oprf_output}.nr` end to end gives the full
    protocol: the client encodes its input to a BabyJubJub curve point (Elligator2,
    `babyjubjub/src/hash_to_curve.nr`), blinds it with a random scalar `beta`, sends the
    blinded point to the committee; the committee applies its secret key `sk` to that point
    and returns the result plus a Chaum-Pedersen proof (Fiat-Shamir via
    `TaceoLabs/noir-poseidon` v0.6.1's `t16` permutation — **a different, independently
    parameterized Poseidon2 instantiation from `noir-lang/poseidon`**, confirmed by reading
    both sources directly, not assumed; entry 75 already found this same non-interchangeability
    for a different pair of Poseidon2 variants) that it used the same `sk` as its published
    public key; the client unblinds by `beta`'s inverse and derives the final output via a raw
    (non-sponge) Poseidon2 permutation over `[ds_out, query, response.x, response.y]`.

    Every piece of that was independently portable and independently checkable against real
    known-answer vectors already embedded in the vendored source — none of this was written
    from a spec and hoped to be right:

    - **BabyJubJub curve arithmetic** — plain Rust over `ark_bn254::Fr` coordinates (twisted
      Edwards, `a=168700`/`d=168696`), checked against `babyjubjub/src/lib.nr`'s own subgroup
      test vectors.
    - **`TaceoLabs/noir-poseidon` v0.6.1's `t3`/`t16` permutation** — round constants were
      mechanically extracted (a Python script parsing the real vendored `consts.nr`, not
      hand-typed) and the round structure (external/internal linear layers, `x^5` S-box)
      ported line-for-line from `permutation.nr`. Checked against `permutation.nr`'s own
      embedded `test_3`/`test_16` vectors — 4 vectors, all bit-for-bit.
    - **Elligator2 `encode()`** — ported using `ark_ff`'s own `Field::sqrt`/`Field::legendre`
      rather than re-deriving `hash_to_curve.nr`'s constrained sqrt/Legendre witnessing scheme
      (that machinery exists only to make the computation *provable* in-circuit; reusing an
      already-correct general-purpose square-root routine is lower-risk than porting a second
      one by hand). Checked against all 3 of `hash_to_curve.nr`'s own `encode()` KAT vectors.
    - **The raw `t=4` Poseidon2 permutation** `generate_output` calls directly (no sponge, no
      capacity/IV slot — all 4 inputs are message) — a second, minimal copy of the exact same
      round constants `pallets/poseidon2-bn254` already validated (that crate only exposes its
      sponge wrapper publicly, not the raw permutation this specific call needs), checked
      against the same free `acvm-repo/bn254_blackbox_solver::poseidon2::tests::smoke_test`
      vector that crate's own tests use.
    - **Chaum-Pedersen proof generation** — the one piece with no upstream implementation at
      all to port, since `oprf-nr` only ever verifies. A standard sigma-protocol prover
      (sample nonce, commit, Fiat-Shamir via the same `t16` transcript the verifier
      recomputes, respond `s = r + e·x mod BABYJUBJUB_Fr`) for the exact relation
      `verify_dlog_equality` checks.

    **The strongest validation isn't any single KAT — it's that the assembled pipeline
    reproduces `oprf_output.nr`'s own full `verified_oprf_kat_test`** (a fixed
    beta/pk/dlog_e/dlog_s/response/response_blinded/client_input/ds_dlog/ds_out tuple with a
    published expected output) bit-for-bit, meaning every module above is not just
    individually correct but correctly wired together. On top of that, this session's
    `blinded_query` was cross-checked against a **real `nargo execute --package
    oprf_identity_anchor_query`** run of the actual (not stubbed) circuit in this repo, over
    that circuit's own committed `Prover.toml` fixture — the strongest available evidence that
    this port matches what the deployed circuit expects, not just what `oprf-nr`'s own
    unrelated test vectors expect.

    `identity_input` for that fixture (`identity_anchor::derive_identity_input(SAMPLE_DG1)`,
    `0x27e62fda546af6970d595963b00dbb8af2ae8fe08060b48e40c3e3d29cab6b46`) was obtained the same
    way entries 75/76 established for Poseidon2 ground truth: a throwaway `nargo test

    ## What this crate is, concretely

    `oprf-committee-dev/` — a new, standalone top-level Rust crate (its own `[workspace]`,
    deliberately **not** a member of the root `Cargo.toml`; it has nothing to do with the
    runtime/node build graph). `cargo test` (24 tests, all passing) runs every KAT check
    above; `cargo run --bin generate_anchor_prover_toml` runs the simulated flow once (5 fresh
    in-memory committee key pairs, one shared blinded query, 5 independent DLEQ proofs) and
    prints a `Prover.toml` for the `anchor` circuit. See `oprf-committee-dev/README.md` for
    the full module-by-module breakdown and — importantly — its own explicit list of what is
    NOT simulated.
