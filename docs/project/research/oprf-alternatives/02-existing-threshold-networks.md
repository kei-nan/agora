# Reusing an Existing Threshold-Crypto Network

*Research round, 2026-08-11. Question asked: instead of bootstrapping Agora's own 5×35-member OPRF
committee from nothing, can we consume an already-live, already-decentralised threshold-crypto
network — one with real operators, uptime history and (ideally) economic security?*

## The test every candidate has to pass

Agora needs a **blind** evaluation: the network applies a secret key to an input it never sees, and
the client gets a deterministic output it cannot compute itself. Threshold *signing* and threshold
*decryption* are not automatically this primitive.

Two facts shape the whole evaluation:

1. **Threshold BLS is mathematically already an OPRF.** A BLS signature is `H(m)^k`; a 2HashDH OPRF
   output is `H(hashToCurve(x)^k)`. Any threshold-BLS network is *one API call away* from being an
   OPRF — but every deployed one hashes the message internally, so a client cannot submit a
   pre-blinded group element. The missing piece is an endpoint, not a new cryptosystem.
2. **That endpoint can never be added to a production key.** A "raise this caller-supplied point to
   the network key" oracle destroys the security of whatever else that key does. On drand it would
   let anyone precompute all future beacon rounds. On tBTC it would expose the signing key's
   behaviour on chosen points. On IC's vetKD it would break every application's per-identity access
   control at once. So reusing a live network always means: **a fresh, dedicated key, generated by a
   new DKG among those same operators, running a new service.** You reuse the *operators and the
   software*, never the existing key material.

That reframing is the single most useful result of this round: "reuse a live network" collapses into
"recruit an existing operator set" (a governance/BD problem) plus "reuse audited code" (an
engineering saving). Those two are separable, and Agora should take the second without the first.

## Candidates evaluated

### Internet Computer vetKeys / vetKD (DFINITY)

**What it is.** vetKD (verifiably encrypted threshold key derivation, [ePrint
2023/616](https://eprint.iacr.org/2023/616)) derives a per-identity BLS12-381 key from a subnet's
threshold master key, returning it encrypted under a caller-supplied transport public key so neither
the nodes nor the calling canister learn the derived key. The production key `Bls12_381_G2:key_1`
lives on the 34-node fiduciary subnet `pzp6e`, generated and enabled in June 2025 with a reshared
backup on the II subnet ([forum
thread](https://forum.dfinity.org/t/vetkeys-production-key-and-ii-subnet-downtime/50370)), and the
Niobium milestone made it a supported mainnet feature.

**Blind-OPRF suitability: no, and not fixable by Agora.** vetKD hides the *output*, not the *input*.
The derivation input travels as an ordinary management-canister call through replicated consensus,
and IC's own security docs state plainly that "canisters provide integrity but not confidentiality"
— canister data can be read by the nodes ([security best
practices](https://docs.internetcomputer.org/building-apps/security/data-storage)). Passing a
national ID to a canister publishes it to 34 node providers. Worse, `vetkd_derive_key` is callable
by anyone willing to pay ~$0.036 per call ([cycle
costs](https://docs.internetcomputer.org/references/cycle-costs/)), so even without node access an
attacker can grind a low-entropy national-ID space against published anchors. Making it oblivious
requires a new blinded-input endpoint in the IC protocol itself plus a dedicated master key — an
NNS-governed DFINITY roadmap item, not something Agora can build.

**Decentralisation / maturity.** Genuinely strong on paper: ~56 node providers, target topology
reached in 2023, 34-node production subnet, and a Swiss "national subnet" of 13 Swiss/Liechtenstein
providers launched at Davos 2026 — a real precedent for government-adjacent deployment. Uptime is
good but not absolute; the vetKeys key rollout itself required a 15-minute planned halt of the II
subnet.

**Integration cost.** Ironically the *lightest* of any candidate if the crypto worked: IC responses
are certified by a subnet threshold-BLS signature chaining to a fixed root key, verifiable with a
single signature check and **no light client** ([certified
data](https://docs.internetcomputer.org/concepts/certified-data/)). A Substrate pallet doing
BLS12-381 verification is real but bounded work. Moot, given the blindness gap.

**Governance risk.** Node providers are admitted by NNS proposal, and NNS voting is ICP-stake-
weighted ([node provider
onboarding](https://wiki.internetcomputer.org/wiki/Node_Provider_Onboarding)). So operator admission
is a token-weighted decision by an external DAO — structurally the plutocratic control the project
already rejected for its own committee, just outsourced.

### Human Network (human.tech / Holonym) — the best true live vOPRF

**What it is.** A threshold **2HashDH vOPRF** network purpose-built for exactly Agora's use case:
deriving stable keys and unlinkable identity nullifiers from low-entropy human inputs. Live, with
"more than 2.5 million keys" created, running as an AVS restaked on EigenLayer and Symbiotic
([announcement](https://human.tech/blog/reintroducing-human-network-s-voprf)). Its own repo
describes it as a "blind, decentralized elliptic curve point by scalar multiplication network"
computing `hashToScalar(k * hashToCurve(x))`, with prover / relayer / verifier / attestor node roles
and DLEQ proofs — [github.com/holonym-foundation/human-network](https://github.com/holonym-foundation/human-network),
**MIT licensed**.

**Blind-OPRF suitability: yes, natively.** This is the real thing, including proactive resharing
each epoch (mobile-adversary tolerance) which preserves the key — and therefore anchor stability —
across operator churn.

**Decentralisation / maturity.** Claims are inconsistent across their own pages: "27 nodes… two-
thirds threshold quorum for 25 nodes" in one post, "6-of-8 threshold network with 28 nodes" in
another. I could not verify the operator list, the admission policy, or the Halborn audit report
from public sources. Restaked ETH ($1.4B–$2.5B depending on the post) buys less than it sounds:
restaking slashes *attributable* faults, and a leaked OPRF key share is not attributable — the
economic security covers liveness, not the confidentiality property Agora actually depends on. The
open-source repo shows 44 commits and 2 stars: a small, young codebase with essentially no external
review.

**Integration cost for Agora: high, and this is the killer.** Agora's Noir circuits are already
committed to a *specific* OPRF protocol — TACEO's `oprf-nr`, on **BabyJubJub** with TACEO-flavoured
Poseidon2 and a Chaum-Pedersen DLEQ, with `DS_DLOG` "deliberately kept byte-identical" to the value
TACEO's `oprf-service` is driven with in production
(`circuits/oprf-identity-anchor/lib/identity-anchor/src/lib.nr:52-58`). Human Network's curve and
hash are different; adopting it means rewriting the anchor/disclosure/migrate circuits and
re-deriving every proving artefact. That cost dwarfs the committee-bootstrapping cost it would save.

**Governance risk.** A single venture-backed company's roadmap, mid-pivot (Gitcoin Passport
acquisition, 34.5M credentials being migrated). Better than a closed vendor because of the MIT
licence — but as a *service dependency* it is the same shape as the TACEO objection.

### TACEO:OPRF — rejected as a vendor, but its code is the answer

The project already rejected consuming TACEO's network (discretionary approval of both operators and
client apps). That rejection still stands: the network is live with ~9 named operators (Nethermind,
P2P.org, InfStones, Stakecraft, Moonli, H2O Nodes, ZKPassport, CTU Prague, TU Graz), operators must
*apply*, and no pricing or SLA is published ([TACEO Network
launch](https://core.taceo.io/articles/taceo-network/)).

**But the rejection was of the network, not the code — and those are separable.**
[`TaceoLabs/oprf-service`](https://github.com/TaceoLabs/oprf-service) is **dual-licensed Apache-2.0 /
MIT**, 924 commits, and ships the server (`oprf-service`), **a DKG (`oprf-key-gen`)**, client crates,
contracts and Circom/Noir circuits. Agora's own `oprf-committee-dev/README.md` already describes it
as "a separate, self-hostable, third-party-audited Rust service this project has never stood up".
Agora's circuits are already wire-compatible with it by deliberate design. Anyone can run it; TACEO
cannot revoke a permissive licence.

This is the finding that matters most: the ~35-member-committee plan's largest unbuilt risk is not
governance, it is *the DKG, resharing and node service software* — and that software exists, is
permissively licensed, is running in production behind World ID, and is the exact protocol Agora's
circuits already speak.

### Threshold Network (Keep + NuCypher)

Primitives are proxy re-encryption / conditions-based threshold decryption (TACo) and threshold
ECDSA (tBTC). **Neither is a blind evaluation**: threshold decryption returns what you encrypted,
producing no key-derived deterministic output; ECDSA is not a PRF. Adapting the tECDSA node set to
blind secp256k1 scalar multiplication means a new endpoint, a dedicated key, node-software changes
and DAO approval — i.e. all the work of a new network with none of the code reuse, on the wrong
curve for Agora's circuits. The organisation has also refocused on Bitcoin finance, with TACo being
handed to the World Ethical Data Foundation and a fork/relaunch planned for H2 2026 — continuity
risk on top of a primitive mismatch. **Not viable.**

### drand / League of Entropy

Produces *public* randomness — one output per round, no per-input evaluation — and, as argued above,
can never expose blind evaluation on its beacon key without total compromise. **Not reusable as an
OPRF, full stop.**

Its value here is as **governance evidence**, and it is strong evidence. The mainnet League lists
~17 named organisations — Cloudflare, Ethereum Foundation, Protocol Labs, Kudelski Security,
ChainSafe, Emerald Onion, plus universities (EPFL, UCL, Chile, Catalonia, Lucerne, Chengdu) and
C4DT ([drand.love/loe](https://drand.love/loe/)). Vetting is explicit: demonstrated "previous
experience with operating critical infrastructure", a DDoS-resistant self-contained stack, and
graduation from testnet by showing operational excellence. Result:
[status.drand.love](https://status.drand.love/) shows **100.0% 90-day uptime** on the mainnet beacon,
with the only 2026 incident (22 April) hitting *relays*, not the beacon.

### Others checked

- **Sui Seal** (Mysten) — threshold IBE key servers; mainnet 2026 with a **5-of-8 institutional
  committee** of named node operators. Same non-blind-input limitation as vetKD. Another data point
  for the institutional pattern.
- **Lit Protocol (Naga)** — V1 mainnet DKG performed 17 Dec 2025 with **7 node operators**; identity-
  based BLS encryption via MPC TSS **plus TEEs**. Input confidentiality would rest on hardware
  attestation rather than cryptography, and the network just force-migrated its entire v0 user base
  (Datil shutdown Feb 2026). Roadmap/token churn; not a base for a national eligibility gate.
- **Generic MPC networks (Nillion, Partisia, Arcium-class)** — could in principle host a keyed PRF
  over secret-shared state, which is *stronger* than an OPRF. But you would deploy your own program
  and run your own key ceremony, so you are buying hosting and trust distribution, not a ready OPRF
  — and Nillion's Blacklight nodes are admitted by **70,000 NIL stake**, i.e. the stake-weighted
  operator admission the project already rejected on principle.

## The institutional-operator model, revisited

Changelog #082 set this aside "for the founding phase, not decided against permanently", and said it
deserved its own adversarial round. Here it is.

**The case for is stronger than it looked.** Every production threshold network surveyed here
converged independently on 7–35 *named, professionally operated* nodes: drand 17, IC subnets 13–34,
Seal 5-of-8, Lit 7, TACEO 9, Human Network ~25. Zero converged on sortition-selected amateurs. That
is not fashion; the operator role has a hard floor of DDoS resistance, key custody, patch response
and 24/7 availability that a randomly selected citizen with a project-supplied phone cannot meet.
Choosing institutions also dissolves the three unresolved items in changelog #082 in one move:
device custody (orgs already run HSMs), fleet-update authorisation (each org patches its own node),
and DKG logistics across heterogeneous member-owned devices.

**The accountability trade is real but it does not run the way the earlier notes assumed.** The
citizen model's claimed advantage is that a randomly chosen citizen is a harder target than a named
institution. For Agora's stated threat model — a government platform where the plausible adversary
*is* a captured state — that advantage is mostly illusory: the committee roster is public on-chain
by construction, and **all 35 sortition-selected citizens live inside the adopting country's
jurisdiction**. A state that can subpoena, prosecute or simply visit 12 of 35 of its own citizens
defeats the threshold. Named institutions are individually more coercible per unit of pressure, but
they can be chosen for *jurisdictional diversity* in a way citizens of one country structurally
cannot. A committee split across a domestic university, a domestic civil-society org, a foreign
university, an international election-monitoring body and an infrastructure operator on another
continent is genuinely harder for any single government to reach the threshold of than 35 domestic
citizens. drand's League is exactly this shape and is what makes it credible.

**The honest costs.** (a) Legitimacy: sortition is part of Agora's democratic story, and "five
universities and an NGO hold the key to voter eligibility" is a weaker public message, easier to
attack as technocratic. (b) Capture-over-time: institutions are permanent, accrue relationships, and
can be captured slowly in ways a rotating citizen pool cannot; the mitigation is mandatory rotation
and scheduled rekeying, which Agora's 4-year scheme-version rotation already provides. (c)
Recruitment is a political project — signing an international monitoring body is slower than drawing
35 names. (d) Anti-plutocracy holds either way: appointment is by governance, not stake.

**Recommended shape: a hybrid that keeps the democratic control where it matters.** Institutions
*operate*; citizens *govern*. Keep the sortition apparatus for the appointment, audit and removal of
operators (a standing citizen oversight panel with the power to propose removal via the existing
Emergency Council + Courts AND-gate), and keep the 5-committee hashed-summation structure — it maps
cleanly onto five independent institutional slots and preserves the "one honest committee suffices"
property. This is a strictly better use of sortition than having citizens run servers: the machine
work is mechanical and needs no human judgement (changelog #082 says so itself), while the *choice*
of who holds key shares is precisely a judgement call worth democratising.

## Integration feasibility with Agora's stack

- **Client side is already done and network-agnostic.** Blinding, DLEQ verification, unblinding,
  hashed summation across 5 committees and `migrate_oprf_scheme` all live in the circuits and
  `pallet-identity` already. Swapping who holds the key changes transport and roster, not client
  crypto — *provided the protocol stays `oprf-nr`/BabyJubJub*.
- **The cheapest concrete path** is to stand up `TaceoLabs/oprf-service` (Apache-2.0/MIT) five times
  under Agora's own governance, using its bundled `oprf-key-gen` for the five DKGs, with
  `pallet-identity`'s existing `OprfCommitteeKeys` allowlist as the on-chain source of truth. This
  replaces the largest unbuilt, unaudited chunk of the plan with production-proven code without
  taking any vendor dependency.
- **Keep the on-chain mailbox.** Whatever the operator set, the mailbox
  (`submit_oprf_query`/`submit_oprf_response`) is what lets Agora gate queries on a valid passport
  proof and thereby **rate-limit brute-forcing of low-entropy national IDs**. Moving to an external
  network's HTTP endpoint hands that control to someone else — none of the candidates publishes a
  contractual guarantee about query rate limiting, and it is the property Agora's whole
  Sybil-resistance story rests on. This alone argues against consuming any foreign network.
- **Bootstrap option worth taking now.** TACEO offers a free test tier
  (`test.oprf.taceo.network`), protocol-identical to Agora's circuits. Using it in testnet would
  unblock the project's #1 item — the first genuine end-to-end ZKPassport→verifier proof — *today*,
  with zero lock-in, since the production deployment would be Agora's own instances of the same
  software.

## Open questions

1. Does `oprf-service`'s `oprf-key-gen` support **resharing** to a changed operator set, or only a
   fresh DKG? Agora's 4-year rotation assumes fresh DKG, so this may not matter — but emergency
   single-committee replacement does depend on it.
2. What is the third-party audit that `oprf-committee-dev/README.md` attributes to `oprf-service` —
   who did it, what scope, is the report public? Not verified in this round.
3. Human Network's contradictory node counts (25 vs 28) and its 6-of-8 vs 2/3 threshold claims;
   its Halborn report was not locatable.
4. Does running `oprf-service` require its Ethereum contracts / anvil coordination layer, or can the
   roster and key allowlist be driven entirely from `pallet-identity`? The repo's `just run-setup`
   orchestrates anvil + Postgres, which suggests a chain dependency to be excised.
5. Network-layer anonymity of the query path is still open (unchanged from changelog #073): an
   operator that sees source IPs learns *who registered when*, even without the input.
6. Would credible institutions actually sign up before there is a real deployment? Untested.

## Verdict

**Do not consume anyone else's live network as the production eligibility gate — but do take their
code and their operator model.** The strongest candidate on pure cryptography, Human Network, is
ruled out on integration grounds (wrong curve; Agora's circuits are already committed to TACEO's
`oprf-nr` on BabyJubJub), and vetKeys — the most promising-sounding lead — turns out not to be blind
at all: the derivation input is visible to the subnet, and IC's own docs concede canisters give
integrity but not confidentiality. The recommendation is therefore a two-part swap of *how* rather
than *what*: run Agora's own five committees on `TaceoLabs/oprf-service` (permissively licensed,
DKG included, protocol-identical to the circuits already written), and staff them with ~8–15 named,
**jurisdictionally diverse** institutions vetted on drand's critical-infrastructure criteria, with
sortition-selected citizens holding appointment, audit and removal power rather than holding the
servers. The single biggest risk this does not solve: whoever holds the key can still grind a
low-entropy national-ID space against published anchors, so the on-chain, proof-gated query mailbox
that rate-limits evaluations is not an implementation detail to be traded away for a convenient HTTP
endpoint — it is the security boundary, and it is the one thing no external network will give you.
