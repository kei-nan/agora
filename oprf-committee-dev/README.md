# `oprf-committee-dev`

**DEV/TEST-ONLY.** This is a local simulator that plays the role of `circuits/oprf-identity-anchor`'s
5 OPRF committees well enough to produce protocol-correct proving inputs for the `anchor`/
`disclosure`/`migrate`/`migrate-disclosure` circuits. It is **not**, and must never be treated
as, a production OPRF committee service. See `docs/project/changelog/078.md` for the full
session record (what was built, what was checked, what remains).

## What this is

`TaceoLabs/oprf-nr` (the Noir library `circuits/oprf-identity-anchor` imports, pinned tag
`v1.0.0`) implements the *client and verifier* side of an OPRF protocol: blind a query, verify
a committee's Chaum-Pedersen proof that it applied its secret key correctly, verify the client
unblinded correctly, derive the final output. It has never had to implement the *committee*
side — the actual secret-key holder that receives a blinded query and returns an evaluation —
because that's `TaceoLabs/oprf-service`'s job, a separate, self-hostable, third-party-audited
Rust service this project has never stood up (see the circuit README's "What is NOT done").

Every proof this circuit workspace has produced until now (changelog entries 69-77) substituted
`oprf_proof.beta` directly for what a committee's evaluation would return — a passthrough that
satisfies the same *public-input shape* `verified_oprf` expects but exercises none of its actual
checks (the DLog-equality verification, the unblinding check). This crate closes that gap for
local dev/testing: it is a from-scratch, from-first-principles Rust implementation of the actual
math a committee member performs, plus 5 independent in-memory key pairs standing in for the 5
committees changelog entry 73 decided on.

## What is real here

- **BabyJubJub curve arithmetic** (`babyjubjub.rs`) — full Edwards addition/scalar
  multiplication, validated against `oprf-nr`'s own subgroup-check test vectors.
- **`TaceoLabs/noir-poseidon` v0.6.1's Poseidon2 permutation** (`poseidon2_taceo.rs`, widths 3
  and 16) — a **different, independently-parameterized Poseidon2 instantiation from
  `noir-lang/poseidon`** (the one `pallets/poseidon2-bn254` in the main repo already ports;
  changelog entry 75 found the two are not interchangeable). Needed because `dlog.nr`'s
  Chaum-Pedersen challenge and `hash_to_curve.nr`'s `hash_to_field` both explicitly
  `use poseidon2::bn254::permutation`. Round constants were mechanically extracted from the
  real vendored source (a script, not hand-typing) and validated against real test vectors
  embedded in that same source file.
- **Elligator2 hash-to-curve** (`hash_to_curve.rs`) — ported using `ark_ff`'s own
  `Field::sqrt`/`Field::legendre` rather than re-deriving `oprf-nr`'s constrained
  sqrt/Legendre witnessing scheme (lower risk: reuses an already-correct general-purpose
  routine instead of a second hand-rolled one). Validated against all 3 of `oprf-nr`'s
  `encode()` known-answer vectors, AND against a real `nargo execute --package
  oprf_identity_anchor_query` run of the actual circuit in this repo (see `oprf.rs`'s
  `blinded_query_matches_the_real_query_circuit_execution` test).
- **Chaum-Pedersen DLog-equality proof generation** (`dlog.rs`) — the one piece with no
  upstream implementation to port (`oprf-nr` only ever verifies this proof). A standard
  sigma-protocol prover for the exact relation `verify_dlog_equality` checks, validated by:
  (a) `verify()`'s Rust mirror passing `oprf-nr`'s own fixed KAT, and (b) — far more
  importantly — every `generate()`d proof this crate produces being accepted by the REAL,
  unmodified `verified_oprf` Noir call inside the real `anchor`/`disclosure` circuits (see
  below).
- **The raw (non-sponge) `t=4` Poseidon2 permutation** `generate_output` needs
  (`noir_poseidon2.rs`) — a second, minimal copy of the exact same already-validated
  round constants `pallets/poseidon2-bn254` uses (that crate only exposes the sponge, not
  the raw permutation `oprf_output.nr` calls directly), validated against the same free
  `bn254_blackbox_solver` smoke-test vector that crate's own tests check.
- **5 independent in-memory committee key pairs** (`committee.rs`) — freshly generated per
  run, each correctly evaluating the shared blinded query under its own secret key.

## What is emphatically NOT real here — read this before reusing any of it

- **No real key ceremony.** All 5 secret keys are generated by one process's RNG in one call.
  Changelog entry 73's actual design (5 independent ~35-member committees, each running its
  own founding DKG) is untouched by this crate — that is a human/governance problem, out of
  scope here by explicit instruction.
- **No distinct parties, no network protocol.** A real deployment is `TaceoLabs/oprf-service`
  instances run by independent operators, talking to clients over a real API. Here, "client"
  and all 5 "committees" are function calls in the same process.
- **No threshold secret sharing within a committee.** Changelog entry 73's ~35-member
  committees presumably split each committee's key across members (the point of "committee"
  rather than "single server"); this crate gives each committee one flat secret scalar.
- **Not audited, not fuzzed, not constant-time.** This is proving-input generation for local
  dev/test only. Do not use these keys, this RNG usage, or this code path for anything a real
  human's identity depends on.

## What this closes, concretely

All four of `circuits/oprf-identity-anchor`'s committee-consuming circuits — `anchor`,
`disclosure`, `migrate`, `migrate-disclosure` — have now been proven and verified
**end-to-end with real bb 5.0.0** using this crate's simulated committee output in place of
the `oprf_proof.beta` stub: a genuine witness was solved (every `verified_oprf` call's
Chaum-Pedersen and unblinding checks actually passed, not vacuously satisfied), a proof was
generated, and `bb verify` accepted it. `anchor`/`disclosure` were closed in changelog entry
078; `migrate`/`migrate-disclosure` in entry 081, using two independent committee-key
generations (`generate_migrate_prover_toml`/`generate_migrate_disclosure_prover_toml`,
10 `verified_oprf` calls per proof instead of 5). Entry 081's `old_oprf_proofs` deliberately
replays entry 078's exact committee generation (same RNG seed, same beta) as a cross-check:
`migrate`'s `old_anchor` output matched `anchor/Prover.toml`'s already-proven `anchor` value
byte-for-byte. See `docs/project/changelog/078.md` and `081.md` for exact commands and output.

## Layout

- `src/scalar.rs` — arithmetic mod `BABYJUBJUB_Fr` (the curve's own subgroup order, distinct
  from BN254's scalar field everything else here uses for coordinates/hashing).
- `src/babyjubjub.rs` — the curve group.
- `src/poseidon2_taceo.rs` — `TaceoLabs/noir-poseidon` v0.6.1's `t3`/`t16`.
- `src/hash_to_curve.rs` — Elligator2 `encode()`.
- `src/noir_poseidon2.rs` — the raw ACIR-blackbox `t=4` permutation (`generate_output`).
- `src/dlog.rs` — Chaum-Pedersen verify (mirror) + generate (the committee's actual job).
- `src/oprf.rs` — client/committee protocol glue (`blinded_query`, `evaluate`, `unblind`,
  `generate_output`).
- `src/committee.rs` — the 5-committee dev simulator.
- `src/prover_toml.rs` — renders a `Prover.toml` for the `anchor`/`disclosure`/`migrate`/
  `migrate-disclosure` circuits from simulated output. `generate_proof_set` runs one full
  client+committee-generation round (used once by `anchor`/`disclosure`'s driver, twice by
  `migrate`/`migrate-disclosure`'s).
- `src/bin/generate_anchor_prover_toml.rs` — the driver used in changelog entry 078: runs the
  simulated flow once for the `query` circuit's own committed fixture and prints an
  `anchor`-shaped `Prover.toml` to stdout.
- `src/bin/generate_migrate_prover_toml.rs` / `generate_migrate_disclosure_prover_toml.rs` —
  the drivers used in changelog entry 081: run the simulated flow twice (old committee
  generation — byte-identical to `generate_anchor_prover_toml`'s recipe — then an
  independently-generated new one) and print a `migrate`/`migrate-disclosure`-shaped
  `Prover.toml`.
- `src/ffi.rs` — changelog entry 082's wasm packaging: a thin C-ABI wrapper around
  `oprf::evaluate` only (the real, already-validated committee-evaluation function described
  above under "What is real here" — not `committee.rs`'s 5-committee dev simulator and not
  `prover_toml.rs`'s Prover.toml rendering, neither of which this module touches or exposes).
  This is what compiles to `wasm32-unknown-unknown` (`cargo build --release --target
  wasm32-unknown-unknown --lib`, enabled by this crate's `[lib] crate-type = ["cdylib",
  "rlib"]`) so the identical evaluation logic can run inside a Wasm runtime (wasmtime/wasmer)
  on a committee member's phone, laptop, or Raspberry Pi, per changelog entry 082. See its
  module-level doc comment for the exact wire format (fixed-width big-endian byte layout) and
  `tests/wasm_equivalence.rs` for the proof that the compiled `.wasm` produces byte-identical
  output to the native build. This module changes nothing about this crate's own dev/test-only
  status — it packages already-real code, it doesn't make the simulator itself production.

## Reproducing

```bash
cd oprf-committee-dev
cargo test          # unit tests: KAT vectors from oprf-nr/noir-poseidon, plus a real
                     # nargo-execute cross-check of the query circuit
cargo run --bin generate_anchor_prover_toml > /tmp/anchor_prover.toml
cp /tmp/anchor_prover.toml ../circuits/oprf-identity-anchor/anchor/Prover.toml

cd ../circuits/oprf-identity-anchor
nargo execute --package oprf_identity_anchor anchor_witness
nargo compile --package oprf_identity_anchor
mkdir -p target/bb_anchor
bb write_vk --scheme ultra_honk -b target/oprf_identity_anchor.json -o target/bb_anchor
bb prove    --scheme ultra_honk -b target/oprf_identity_anchor.json \
            -w target/anchor_witness.gz -k target/bb_anchor/vk -o target/bb_anchor
bb verify   --scheme ultra_honk -k target/bb_anchor/vk \
            -p target/bb_anchor/proof -i target/bb_anchor/public_inputs
```

`migrate`/`migrate-disclosure` follow the identical pattern with their own binaries:

```bash
cd oprf-committee-dev
cargo run --bin generate_migrate_prover_toml > /tmp/migrate_prover.toml
cp /tmp/migrate_prover.toml ../circuits/oprf-identity-anchor/migrate/Prover.toml
cargo run --bin generate_migrate_disclosure_prover_toml > /tmp/migrate_disclosure_prover.toml
cp /tmp/migrate_disclosure_prover.toml ../circuits/oprf-identity-anchor/migrate-disclosure/Prover.toml

cd ../circuits/oprf-identity-anchor
nargo execute --package oprf_identity_anchor_migrate migrate_witness
nargo execute --package oprf_identity_anchor_migrate_disclosure migrate_disclosure_witness
nargo compile --workspace
mkdir -p target/bb_migrate target/bb_migrate_disclosure
bb write_vk --scheme ultra_honk -b target/oprf_identity_anchor_migrate.json -o target/bb_migrate
bb prove    --scheme ultra_honk -b target/oprf_identity_anchor_migrate.json \
            -w target/migrate_witness.gz -k target/bb_migrate/vk -o target/bb_migrate
bb verify   --scheme ultra_honk -k target/bb_migrate/vk \
            -p target/bb_migrate/proof -i target/bb_migrate/public_inputs

bb write_vk --scheme ultra_honk -b target/oprf_identity_anchor_migrate_disclosure.json -o target/bb_migrate_disclosure
bb prove    --scheme ultra_honk -b target/oprf_identity_anchor_migrate_disclosure.json \
            -w target/migrate_disclosure_witness.gz -k target/bb_migrate_disclosure/vk -o target/bb_migrate_disclosure
bb verify   --scheme ultra_honk -k target/bb_migrate_disclosure/vk \
            -p target/bb_migrate_disclosure/proof -i target/bb_migrate_disclosure/public_inputs
```
